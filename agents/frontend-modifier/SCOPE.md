# SCOPE — frontend-modifier 的设计范畴

本文件定义前端修改 Agent「能做什么、不能做什么」。AGENT.md 的文件边界（白名单/黑名单）始终优先于本文件。

# 设计范畴

## 范围内
- 页面布局、间距、对齐
- 颜色、字体、圆角、阴影、图标
- 组件样式与交互状态（hover / active / disabled / loading / empty）
- 动效与过渡
- 响应式与深色模式适配
- 设计令牌（design tokens）的使用与调整

## 范围外
- 业务逻辑、数据计算（如记账金额算法）
- 接口调用、数据结构变更
- 新增第三方依赖
- 架构重构、状态管理重写

## 判断规则
只影响"看起来和用起来的感觉"的，属于范围内。
影响"数据是什么、怎么存、怎么算"的，属于范围外。
拿不准时，先问，不要动手。

## 能做（默认授权）

- **页面 UI 改版**：布局、间距、圆角、字号、配色——配色只用 `src/theme/theme.ts` 既有 token，不发明新色值（用户拍板的除外）
- **深浅双主题适配**：样式函数走 `makeStyles(colors, isDark)` 双参模式，新增颜色必须两主题都有值
- **新增/改造可复用组件**：放 `src/components/`，创建前先全项目查重，避免重复组件
- **动效与触感**：PressableScale 按压反馈、弹簧参数、Haptics 触感档位
- **弹层/浮层**：沿用现有模式（AppDialog 对话框、上拉弹层、居中浮层），不新造弹层形态
- **文案**：一律走 i18n（useT），中英两个语言包同步补键，不硬编码字符串
- **状态补齐**：空态、加载态、错误态的补齐与跨页面统一
- **图标/颜色**：从 `src/constants/categoryAddOptions.ts` 公共池选取，池不够时扩池（改池前必须过 glyphmap 校验）

## 不能做（须停下并回主会话/用户处理）

- **业务逻辑与计算规则**：金额录入算法、宽度装箱算法、统计口径等已校准逻辑不动
- **数据层**：数据库、云同步、存储结构、事务模型
- **导航结构**：不新建页面、不改路由、不改 tabBar
- **依赖**：不安装新包（现有依赖已覆盖渐变/模糊/触感/动效需求）
- **定版参数**：用户手调校准过的数值与形态不得顺手改；具体数值一律以代码现状为准，不誊抄进规则文档
- **共享层**：src/context、src/navigation、src/hooks、src/types 的任何改动
- **删除功能**：UI 改版不得静默删除既有功能（信息、动作、入口都要保留）

## 项目 UI 基准（改动须对齐）

- 设计 token 单一来源：`src/theme/theme.ts`
- 按压反馈统一用 PressableScale；对话框统一用 AppDialog（不用 Alert）
- 选中态、弹层、开关等已有用户定版的形态，先查 GLOSSARY.md 再动手
- 与既有页面保持同一套设计语言：间距体系、圆角体系、字号层级不另起炉灶
