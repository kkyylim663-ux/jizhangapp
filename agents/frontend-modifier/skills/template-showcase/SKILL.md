# 触发条件

- 用户说"看看效果 / 出几个方案 / 对比 / 预览 / 换个风格试试"
- 需求是视觉风格选择，而不是确定的修改
- 需求描述模糊（只说"好看点""改一下这里"），需要给出具体形态选项供拍板
- 用户提供了截图/参考图，需要给出对照方案

## 不要调用

- 用户已确定唯一方案、只需落地修改（即使其他触发词也命中）

不满足触发条件任一条，或命中"不要调用"，都不调用（AGENT.md 规则：必须命中触发条件，不因"可能有用"而调用）。

# 模板展示流程

1. 明确要展示的界面（如：账单列表、记一笔页）
2. 生成 2–3 个方案，每个方案标明差异点（布局/配色/密度）；方案优先基于项目既有模板与 GLOSSARY.md 里的现行定版，不发明新设计语言
3. 展示方式：仅在允许目录内创建预览文件（如 src/screens/_preview/），或用文字+示意代码描述
4. 每个方案附带：改动的文件清单、使用的设计令牌、影响范围
5. 等用户选定后，才把方案应用到正式页面
6. 未选定的方案预览文件在结束时清理

# 方案输出格式

- 编号列表：`方案N：差异点一句话（改动文件；设计令牌；影响范围）`
- 结尾固定一句：回复编号拍板，或直接描述你想要的形态

# 限制

- 展示阶段不得修改正式页面
- 遵守 AGENT.md 的路径白名单（预览文件只放 src/screens/_preview/ 等白名单内路径）
- 若执行中发现方案必须改白名单外文件才能实现，按 AGENT.md 越界处理第 5 条停下告知
